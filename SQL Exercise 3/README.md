# BrightLearn Data Analytics — SQL Foundations (Exercise 03)

This repository contains details and conceptual breakdowns for **Exercise 03: SQL CASE Statements**, a practical, pen-and-paper workbook designed to master conditional row classification within SQL. 

The focus of this exercise is shifting away from simple data retrieval to applying logical rules directly inside queries to build business categories, alerts, and custom reporting tiers.

---

## Repository Contents

This module covers the operational logic for **10 foundational SQL queries** evaluated across 10 distinct, real-world data schemas. The source workbook structures include:

*   **`products` & `products_inventory`:** Catalog price tier classification and physical stock volume alert systems.
*   **`orders` & `payments`:** Transactional value tiering and checking conditional promotion eligibility based on payment limits.
*   **`employees`:** Multi-dimensional tracking combining separate operational fields (department and salary levels) to map corporate hierarchy.
*   **`students` & `attendance`:** Academic scoring distribution maps and performance metrics derived from inline database arithmetic.
*   **`deliveries` & `tickets`:** Fulfillment duration classification and mapping internal database priorities to human-readable system tags.

---

## What to Expect

The repository provides a deep dive into using the `CASE` expression inside the `SELECT` clause to bucket structural data into labeled metrics. 

### Key Concepts Practised
*   **Searched vs. Simple Syntax:** Selecting the appropriate execution structure depending on the complexity of the evaluation rules.
*   **Multi-Conditional Operations:** Combining criteria using `AND`, `OR`, and logical ranges like `BETWEEN`.
*   **Attribute Manipulation:** Forcing specific database output layouts by implementing custom attributes via structural column aliasing (`AS`).
*   **Output Mapping:** Predicting the structural layout and specific data types generated by conditional processing before compilation.

---

## Lab Ground Rules & Constraints

The solutions to this exercise follow rigid instructional standards to guarantee execution precision:

*   **Syntax Case Standards:** Standard query keywords are strictly set in `UPPERCASE` (e.g., `SELECT`, `CASE`, `WHEN`, `THEN`, `ELSE`, `END`, `AS`), while native field identifiers and schema targets remain completely lowercase.
*   **Format Constraints:** The exercise demands a pen-and-paper execution strategy—hand-writing the operational statements alongside cleanly sketched, custom grid layouts of the expected result tables to test structural accuracy.
